# User Flows

## Deacon verifies a need

1. Household submits need or deacon enters need.
2. Need appears as New or Verification Pending.
3. Assigned deacon contacts household.
4. Deacon marks need Verified, Declined, Duplicate, or Elder Review.
5. Verified need may become a Care Case.

Acceptance criteria:
The need has a status, assigned deacon, urgency, sensitivity, and next action.

## Lead deacon runs weekly muster

1. Open Operations Board.
2. Review urgent needs, blocked cases, overdue follow-ups, uncommitted households, threats, and work orders.
3. Open Reports.
4. Generate Weekly Muster Brief.
5. Assign immediate actions.

Acceptance criteria:
The meeting can run from one screen and one report.

## Household reports a need

1. Household opens family app.
2. Selects Report Need.
3. Chooses category, urgency, description, and preferred contact.
4. Submission enters command system as Verification Pending.
5. Assigned deacon is notified.

Acceptance criteria:
The household cannot see other households. Sensitive content is routed into an encrypted or restricted workflow.

## Disaster mode

1. Lead deacon activates Disaster Mode.
2. Household check-ins are requested.
3. Unknown households are listed.
4. Physical checks are assigned.
5. Power, water, food, shelter, transport, medical needs, and injuries are tracked.
6. Disaster brief is exported.
